# 查黑账 · Black Account Checker

对账户、交易和资金流水进行系统性异常检测与风险核查的完整方法论。核心理念：**数据驱动、证据闭环、宁可误报不可漏报**。

## 1. 调查六步法

### Step 1 — 数据清洗
- 统一时间格式、金额单位、账户编码
- 剔除测试交易、冲正交易等噪音
- 标记缺失值与异常字段

### Step 2 — 特征提取
- 提取每笔交易的：金额、频率、时间、对手方、渠道、用途
- 计算账户级指标：日均余额、进出比、最大单笔、最小间隔

### Step 3 — 异常检测
- **金额异常**：大额整数、频繁接近阈值的拆分交易、快进快出
- **时间异常**：非营业时间高频交易、节假日大额
- **对手方异常**：集中转入分散转出、分散转入集中转出、循环转账
- **行为异常**：长期不动户突然激活、睡眠账户大额进出

### Step 4 — 关联分析
- 构建资金网络图谱（账户 → 对手方 → 对手方的对手方）
- 识别闭环回流、归集账户、中转账户
- 交叉比对工商、涉诉、失信等外部数据

### Step 5 — 风险定级
| 等级 | 标准 |
|------|------|
| 🔴 高风险 | 明确涉嫌洗钱/诈骗/挪用，证据链完整 |
| 🟡 中风险 | 多项异常指标吻合，需进一步核查 |
| 🟢 低风险 | 单一异常，可合理解释 |

### Step 6 — 报告输出
- 摘要：总体结论 + 关键发现
- 发现清单：每条异常附带证据索引
- 证据索引：原始数据定位
- 风险定级：逐账户/逐交易
- 建议措施：冻结/上报/继续监控/排除

## 2. 核心红线指标（命中即预警）

| 指标 | 描述 | 典型场景 |
|------|------|----------|
| 拆分交易 | 连续多笔金额接近报告阈值 | 化整为零规避大额报告 |
| 快进快出 | 资金到账后极短时间内转出 | 过渡账户/洗钱通道 |
| 循环转账 | A→B→C→A 形成闭环 | 虚增流水/对敲 |
| 休眠激活 | 长期不动户突然大额进出 | 账户被盗用/出售 |
| 集中分散 | 一笔大额入 → 多笔小额出 | 洗钱分散阶段 |
| 分散集中 | 多笔小额入 → 一笔大额出 | 集资/归集 |
| 高频小额 | 远超正常频率的小额交易 | 撞库测试/盗刷 |
| 对手方黑名单 | 交易对手在涉诉/失信/制裁名单 | 直接关联犯罪 |

## 3. 常用分析工具与命令

> 安全说明 (v1.1.0): 默认禁止网络外发。`curl/wget` 仅允许经 HITL 批准的权威域名白名单 (见 `financial-research-skill`)，且禁止拼接账户明文到 URL (`?account=$ACC` 明文外发已删除)。Python 沙箱规则优先于本节示例。

```bash
# 数据概览
wc -l <file>          # 行数统计
head -5 <file>        # 前5行预览
tail -20 <file>       # 末尾20行

# 字段提取与统计 (CSV 含引号/逗号时优先用 Python csv/pandas，awk 仅用于简单无引号分隔文件)
awk -F',' '{print $3}' <file> | sort | uniq -c | sort -rn  # 按列计数
awk -F',' '{sum+=$4} END {print sum}' <file>               # 金额求和

# Python 稳健版 (推荐)
python3 -c "import csv,collections; print(collections.Counter(r[2] for r in csv.reader(open('<file>',encoding='utf-8-sig'))))"

# 异常筛选 (阈值示例，需按附录校准为绝对值+币种)
awk -F',' '$4 > 1000000' <file>     # 大额交易
awk -F',' '$3 < 5' <file>           # 高频交易
grep -E "^(20[0-9]{2})-(0[0-9])" <file>  # 日期筛选

# 关联分析
sort -t',' -k2,2 <file> | uniq -c -f1       # 按对手方去重计数
sort -t',' -k2,2 -k3,3rn <file> | head -20  # 按对手方+金额排序
```

### 红线阈值校准 (v1.1.0 新增)
- 快进快出: 到账后 ≤30 分钟转出 ≥90% (零售) / ≤4 小时 (对公)，需结合渠道说明。
- 拆分规避: 连续 5 笔以上金额落在报告阈值 90%–100% 区间 (如 4.5–5 万 CNY)。
- 所有金额比较前必须归一到绝对值 + ISO 币种 (见 `financial-parser-skill`)，禁止“万元/亿元”混算。
